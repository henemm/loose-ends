+## Loose Ends (henemm/loose-ends#796)
+
+`scripts/backup-loose-ends-snapshot.sh` schreibt vor dem restic-Lauf jede Nacht einen
+Plain-SQL-Dump von `loose-ends-db` (`pg_dump`, unkomprimiert für restic-Dedup) nach
+`/home/hem/backups/loose-ends/looseends.sql`, lokal nur der jüngste Stand; der Verlauf
+liegt off-site in jedem restic-Snapshot mit Tag `offsite`. Ordner 700, Datei 600: der
+Dump enthält verschlüsselte Apple-Token und Sitzungs-Hashes. Fehlschlag (Endmarke fehlt,
+Tabellenzahl weicht von live ab, `schema_migrations` leer, `docker exec` scheitert) →
+kein Heartbeat-Ping, die ältere Datei bleibt.
+
+Restore: in eine leere Datenbank, in der die Rolle `looseends` schon existiert (der Dump
+enthält `ALTER TABLE … OWNER TO looseends`); ein neuer Container `postgres:18.6` mit
+`POSTGRES_USER=looseends` und `POSTGRES_DB=looseends` legt beides an. Dann
+`psql -v ON_ERROR_STOP=1 -U looseends -d looseends < looseends.sql` (`psql` ≥ 17.6 wegen
+`\restrict`/`\unrestrict` im Dump).
