Datum: 2026-09-29, gefahren vom Orchestrator, nicht vom umsetzenden Agenten

Zweck: pruefstand-mutationstest.txt belegt die Wirkung des Fixes an EINER mutierten Stelle
(device_probe_locked, AC-2). Diese Gegenprobe mutiert eine ANDERE Stelle, damit der Beleg
nicht an einem Einzelfall haengt — und zwar bewusst die Nutzungsmeldung (AC-1), deren Fall
ausschliesslich ueber den primaeren Zweig 'fail "..."; return' anschlaegt. Genau dieser Zweig
wurde vor dem Fix verschluckt.

LAUF 1 - MIT MUTATION

Mutiert: scripts/sim.sh Zeile 385. Der Abbruch ohne Argument liefert Erfolg statt Fehler:
    [ -z "${1:-}" ] && { error "Usage: ./scripts/sim.sh device-test Class[/test]"; return 1; }
wird zu
    [ -z "${1:-}" ] && { error "Usage: ./scripts/sim.sh device-test Class[/test]"; return 0; }

Die Meldung wird also weiterhin gedruckt — nur der Rueckgabewert ist falsch. Die
Sekundaerpruefung (assert_contains auf "Usage: ...") kann das nicht fangen, weil der Text
unveraendert erscheint. Allein der primaere Zweig schlaegt an. Vor dem Fix waere dieser Lauf
gruen gewesen.
